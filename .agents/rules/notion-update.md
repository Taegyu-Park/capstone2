## 기록 가이드라인

1. **정렬 순서 및 기록 위치**:
   - **날짜가 오래된 순(과거 → 최신, 시간 순서)**으로 정렬합니다.
   - 새 업데이트는 `## 업데이트 사항` 섹션의 **맨 아래(가장 마지막 토글 뒤)**에 덧붙여 작성합니다.
2. **작성 형식**:
   - **반드시 토글(`<details><summary>...</summary></details>`) 형태**로 작성합니다.
   - **토글 제목(`summary`)**: "업데이트 한 문장 요약 (YYYY-MM-DD)" 형식으로 작성합니다.
   - **토글 본문**: 세부 배경, 변경 사항, 검증 결과를 들여쓰기(`\t`)하여 하위에 포함합니다.
   ```markdown
   <details>
   <summary>[업데이트 한 문장 요약] (YYYY-MM-DD)</summary>
   	[변경 배경 및 목적 간략 설명]
   	- **무엇이 바뀌었는가**: 구체적인 변경 사항 (설정, 코드, UI, 파이프라인 등)
   	- **왜 그렇게 결정했는가**: 설계 의도, 트레이드오프, 주의점
   	- **어떻게 검증했는가**: 실행한 테스트, 스크립트 결과, 확인된 데이터
   </details>
   ```
3. **원칙**:
   - 단순 커밋 메시지 복사가 아닌, "배경 + 변경 내용 + 검증 결과"를 사람이 읽기 쉽게 재구성하여 작성합니다.
